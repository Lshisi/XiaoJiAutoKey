# 1.1.7 按键模式回归修复与手动验证

本文记录从 `v1.1.6`（`185b3bb`）到 `v1.1.7`（`11d35c8`）源码对照发现的问题，以及 `bugfix/1.1.7-key-mode-regressions` 分支的修复。分支从 `master` 创建，同一份修复同时用于 `codex/v1.1.8`；手动验证时记录实际使用的分支和提交。

修复覆盖五类按键问题和一项提示音配置转换问题。按键问题位于共用引擎、快捷键处理和输出路由，小叽与 DD 都受影响；USB 也使用这些共用逻辑。提示音问题与驱动无关。长按、武学助手及循环新增动作纳入关联检查，但它们属于 1.1.7 新功能，不记为 1.1.6 原有功能的回归。

## 修复内容

| 编号 | 原先的 BUG | 原因 | 修复后的行为 |
| --- | --- | --- | --- |
| K1 | 单独左／右 Ctrl、Shift、Alt 作为切换键时，第一次换段成功，之后卡在该段 | 修饰键松开分支提前返回，只检查组合前缀，没有清除切换键本身的按下状态 | 松开切换键本身或组合所需修饰键，都能复位，下一次按下可继续切换 |
| K2 | 按下 A 后再按 Shift，先松开 A、后松开 Shift；按压模式可能继续连发，独立模式下一次按 A 被忽略 | 用松开事件当时的完整组合查找绑定，漏掉最初按下时记录的普通 A | 按下仍匹配完整组合，松开按主键清除本次物理记录；独立选择保留，按压立即结束 |
| K3 | 单独 F8 作为启停键，按下 F8 后按住 Shift，再依次松开 F8、Shift，下一次 F8 无法启停 | `Shift+F8` 松开事件不匹配普通 F8，启停键的防重复状态未复位 | 按主键松开复位；Raw Input、键盘钩子和鼠标钩子的处理一致 |
| K4 | 单独 Ctrl、Shift、Alt 设为按压连发键时，工具显示运行，重复脉冲却未发送 | 输出路由把连发主键也当成已被物理按住的组合前缀，跳过发送 | 连发主键使用脉冲发送；组合前缀和长按保持仍复用真实修饰键 |
| K5 | 按键页先运行 A、循环页后运行也包含 A 的循环，按键页暂停恢复后，A 反而由循环页优先输出 | 暂停时删除来源登记，恢复时获得更晚的申请顺序 | 暂停、按压优先和前台挂起只释放实际输出，保留仍被选中项的原申请顺序；停止或取消选择时才释放登记 |
| C1 | 从 1.1.6 配置升级后，自定义启停音和音量恢复默认，原来音量 0 的设置可能重新发声 | 改为读取逐事件 `sounds` 时，没有转换原来的六个音频／音量字段 | 没有 `sounds` 的旧配置在读取时转换为逐事件设置，保留自定义路径和音量 0；已有 `sounds` 的配置直接使用其值 |

释放处理还统一转发启停键的松开事件，避免同一主键的另一种组合绑定漏收释放；修正了释放输出后继续引用已删除容器元素的问题。循环按住触发复用相同的释放判定，保留其原有行为。

## 涉及代码

- `include/core/AppTypes.h`、`src/core/AppTypes.cpp`：统一主键松开、所需修饰键松开的判定。
- `src/core/RepeaterEngine.cpp`、`include/core/RepeaterEngine.h`：切换复位、按压／独立释放、逻辑选中状态与实际输出状态的区分。
- `src/app/coordinators/EngineHookCoordinator.cpp`、`src/app/input/GlobalInputHook.cpp`：Raw Input 与钩子通道的启停键复位和释放转发。
- `src/core/InputDriverRouter.cpp`：修饰键作为连发主键时正常发送脉冲。
- `src/core/MacroEngine.cpp`：循环触发与暂停键复用共用释放判定。
- `src/core/ConfigStore.cpp`：旧提示音设置读取时转换，后续仍只保存 `sounds`。

按键规则见 [按键模式与冲突](key-mode-rules.md)，提示音格式见 [提示音配置](sound-cues.md)。

## 验证准备

以下是供维护者执行的 Windows 手动验证步骤，本次未实际运行。

1. 使用独立的程序目录和配置副本，保留日常使用的 `config.json`。程序由维护者自行构建、启动；不要把配置加入发布包。
2. 小叽与 DD 驱动各执行一轮 K1–K5 和模式检查；在 1.1.8 中分别选择对应驱动插件。USB 可用时补充同样的共用逻辑检查；不支持的输出能力按已有提示处理。
3. 除专门验证前台限制外，先关闭“仅游戏客户端前台时生效”。准备互不冲突的启停键、切换键和暂停键，每个场景只启用需要的绑定。
4. 普通输出的间隔先设为 100–200ms。可用离线 [输入查看页](input-viewer.md) 观察 down／up；焦点保持在接收区，鼠标场景的指针也保持在接收区。
5. 输入查看页无法区分物理键与驱动输出。核对持续多轮的事件及间隔，不能把物理按下或系统自动重复当成程序连发。前台限制、武学助手的游戏效果需要在目标游戏中确认。

## K1：切换键松开后可以再次切换

1. 新建两个启用项，键分别为 `1`、`2`，都设为切换模式。启停键设为普通 `Q`，切换键设为 `LShift`。
2. 启动后，连续短按并完整松开 LShift 至少六次。
3. 预期每次只前进一段，按 `1 → 2 → 1 → 2` 循环；保持 LShift 不松开时不会持续换段。
4. 分别改为 RShift、LCtrl、RCtrl、LAlt、RAlt 重复；再改为普通 `R`、组合 `Shift+R` 检查。
5. 组合键分别采用“先松主键”和“先松修饰键”两种顺序。预期下一次完整按下都可换段。增设一个停用段，确认会跳过；分别检查记忆位置开启和关闭时的重启选段。

原版异常：单独修饰键只完成第一次换段。修复预期：每次完整短按均可换段。

## K2：修饰键变化不遗漏按压／独立的释放

### 按压模式

1. 添加 `A` 按压项。启动后执行 `A 按下 → Shift 按下 → A 松开 → Shift 松开`。
2. 预期 A 松开后停止程序连发，松开 Shift 后也不会自行继续。再按住／松开 A，仍能正常启停。
3. 增设 `B` 开关项，开启按压优先。重复上一步，预期 A 接管时 B 暂停，A 松开后 B 恢复。
4. 用 Ctrl、Alt 替换 Shift 重复；组合按压项另检主键先松、所需修饰键先松两种顺序。可支持时用鼠标键重复“按下鼠标键后增加修饰键再松开鼠标键”。

原版异常：A 的按压记录残留，松开后仍连发，按压优先也可能不退出。

### 独立模式

1. 将 A 改为独立模式，关闭防误停，执行 `A 按下 → Shift 按下 → A 松开 → Shift 松开`。
2. 预期已选 A 继续连发；接下来短按 A 一次即可关闭，再短按一次即可重新开启，不需要额外多按一次。
3. 增设独立键 B，确认 A、B 可互相切换；开启防误停后，重复按当前键保持连发，按另一键仍可切换。

原版异常：下一次 A 按下被残留的物理按下记录吞掉。修复预期：松开只清理物理记录，选择与防误停语义保持正确。

## K3：启停键不因松开时的修饰键快照失效

1. 配置普通 `F8` 为启停键，设置一个 `1` 开关项。
2. 执行 `F8 按下 → Shift 按下 → F8 松开 → Shift 松开`。再完整短按一次 F8。
3. 预期第一次启动、第二次停止。重复数轮，并将 Shift 分别替换为 Ctrl、Alt。
4. 启停键改为 `Ctrl+F8`，分别按主键先松和 Ctrl 先松的顺序重复。改为允许的鼠标中键启停时，也检查按下后改变修饰键再松开的场景。
5. 按住启停键触发系统自动重复，预期只切换一次；松开再按才切换第二次。

原版异常：第二次按键不生效，必须额外按一次。修复预期：完整松开后下一次按下即生效。Raw Input 路径需实机确认；无 Raw Input 时的钩子路径本次仅做源码核对，不要求用户改动输入注册。

## K4：单独修饰键作为按压主键可以连发

1. 只添加一个 `LShift` 按压项，间隔 150ms，启停键使用普通 Q，不设置与 Shift 重叠的控制键或组合输出。
2. 启动后物理按住 LShift，观察多轮输出；预期工具持续发送按下／松开脉冲，而非只有物理按下和系统自动重复。
3. 松开 LShift，预期立即结束该项连发。再按住时能够重新开始。
4. 分别替换为 RShift、LCtrl、RCtrl、LAlt、RAlt。停止工具后，把所有物理键松开，再手动按 A，确认没有残留修饰键状态。
5. 另用普通 A 按压、Shift+A 组合输出、单独 Ctrl 长按各检查一轮，确认普通主键脉冲、组合前缀保持和长按保持各自正常。

原版异常：路由在物理按住时直接跳过程序主键的 down。修复预期：连发主键不被当成组合前缀跳过。

## K5：暂停恢复保留先申请者的同键优先权

1. 按键页添加 A 开关项，间隔 150ms，暂停键设为 P，启停键设为 Q。循环页用另一触发键，设置“点击 A，间隔 700ms；点击 B，间隔 100ms”，无限循环。B 用于确认循环仍在执行。
2. 先启动按键页，再启动循环页。预期 A 按按键页节奏输出，B 持续证明循环在运行。
3. 按住 P，再松开。预期暂停期间按键页释放 A，循环不能抢走 A；恢复后 A 继续按原按键页节奏输出。
4. 停止按键页，预期循环取得 A，并按循环步骤节奏输出；停止循环后全部输出释放。
5. 将按键页 A 分别改为独立模式和切换模式。先选中 A，再启动循环，重复暂停恢复。独立关闭或切换到另一段后，循环应能取得 A。
6. 用另一个参与优先的按压键代替 P 接管，结束接管后优先权不变。另开启前台限制，在允许的目标窗口内启动，切出再切回，检查挂起恢复后的顺序。
7. 反过来先启动循环、后启动按键页，确认暂停恢复不会让后启动的按键页抢到 A；两个页面配置不同主键时仍可并行输出。

原版异常：按键页暂停时注销 A，恢复时排到循环后面，仍显示运行但 A 输出被循环压住。

## C1：旧提示音设置转换

1. 准备一份仍保留 1.1.6 旧字段、没有 `sounds` 的配置副本。四个旧自定义音频路径使用可用且容易辨认的文件；按键组音量设为 0，循环组音量设为 25，整组提示音开关保持开启。
2. 用修复版本读取该副本，打开两页提示音设置。预期 `customSoundOn`／`customSoundOff` 对应按键启停事件，`macroSoundOn`／`macroSoundOff` 对应循环启停事件。
3. 预期按键组各事件音量均为 0，按键操作保持静音；循环／录制组各事件音量为 25，对应启停事件使用旧自定义音频。
4. 正常保存后退出，再次启动。预期设置保持，文件只使用 `sounds` 保存音频／音量，不重新写出旧音频／音量字段。
5. 再用一份已经包含 `sounds` 的配置副本验证。即使同时保留不同的旧字段，也应以 `sounds` 为准。没有旧字段的新配置继续使用当前默认音量。

验证需要原有字段或原始备份；已经被 1.1.7 保存并删除的旧值，无法仅靠当前配置还原。这里转换的是配置格式，不移动、删除或替换音频文件。

## 所有模式的关联检查

以下项目在小叽、DD 下分别执行，不能只根据界面“运行中”判定输出成功。每次结束后松开所有物理键，确认程序输出结束且无粘键。

| 范围 | 手动操作 | 预期 |
| --- | --- | --- |
| 开关 | 启停、暂停键、按压优先、前台挂起后恢复 | 正常交替 down／up；暂停时释放，恢复后继续；停止后不再发送 |
| 按压 | 普通键、左右修饰键、组合键、多按压键并行、参与／不参与优先 | 物理条件结束即停止；参与优先结束后其他模式恢复 |
| 独立 | 开启、关闭、换键、防误停、暂停恢复 | 独立选择唯一，松开不丢选择，下一次物理按下不被吞掉 |
| 切换 | 普通／修饰／组合切换键，单段、多段、停用段，记忆位置 | 一次按下只前进一段，跳过停用段，停止重启符合记忆设置 |
| 长按 | 单键、组合、共享修饰键，暂停、切窗、停止 | 保持条件满足时持续保持，主键先释放；一个共享项结束不打断另一项 |
| 武学助手 | 未满 3.1 秒暂停、满时后暂停、按压接管、切窗、手动接管后停止 | 符合按键规则中的计时、关闭短按和手动接管语义；游戏内结果人工确认 |
| 循环开关触发 | 首次启动、再次停止、按住触发键、有限／无限次数、暂停恢复 | 自动重复不重复启停；有限次数结束；暂停后继续；停止释放全部持有键 |
| 循环按住触发 | 主键先松、所需修饰键先松、按下后增加其他修饰键 | 主键或所需修饰键松开即停止，后续能重新启动 |
| 循环动作 | 点击、保持、按下→松开、等待、滚轮，以及这些动作中的暂停停止 | 点击不重发，剩余等待／保持按原规则恢复；停止不留持有键 |
| 程序自身输入过滤 | 长时间运行独立／切换项及合法的组合输出 | 程序输出不被识别为新物理触发，不自行切换、停机或重复播放状态提示 |
| 配置与界面状态 | 停止、停用、切换配置后重新启动 | 不保留上一轮物理按下记录；来源登记在停止／取消选择后释放 |
