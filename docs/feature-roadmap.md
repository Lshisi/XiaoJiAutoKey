## 二、整体界面怎么改

### 2.1 保留现有操作顺序

继续使用左侧导航、中间配置与列表、右侧快捷控制／启动触发／参数设置的布局。启动和停止按钮始终保留在右侧原位置，新增功能不占用现有“使用统计”等页面的位置。

优先把新入口放在现有工具栏、行菜单和弹窗中。本轮已选功能不需要增加一级导航。

```text
左侧导航       中间工作区                         右侧控制区
──────────    ──────────────────────────────    ──────────────
按键连发       配置：[配置选择器] [启用]          快捷控制
循环连发       [+] [更多⋯] [分享]                 [启动／停止]

               选择／按键／名称／模式／间隔／操作  ──────────────
               ……                                当前页面参数
```

此图表达入口关系；实际控件按宽度换行，不把整行固定塞进窄窗口。

### 2.2 工具栏和列表的统一做法

- 配置选择器占据弹性宽度，新增、复制和导出保留单行图标入口；重命名及删除收进“更多”菜单。删除继续保留确认，并与常用动作分组。
- 列表保持现有紧凑行高；按键与名称分列显示，名称列默认约 80 逻辑像素，其余宽度分给按键、模式、优先和间隔列，窗口加宽时不再单独拉长名称。长名称省略，完整内容放入 tooltip 和可访问名称。
- 按键与循环列表常驻独立选择框，勾选后显示批量操作；两边的启用开关均位于操作列前，行内删除使用垃圾桶图标。两边均支持批量删除并确认数量；循环步骤停用后保留配置，执行时跳过该步骤及间隔。
- 循环预览时长放在列表下方，不挤占右侧启动按钮原有位置。
- 按键总览使用按需打开的辅助弹窗；主列表继续作为日常编辑入口。

### 2.3 样式、缩放与交互约束

- 沿用默认 780×560 窗口、最大高度 700、侧栏宽 130、正文 12、卡片标题 15、页面标题 19 的现有规格。
- 使用现有 `Theme.qml`／设计 token、`Quiet*` 控件、`ActionButton`、`IconButton` 和 `DialogShell`。普通按钮、图标按钮和启动按钮以 32 逻辑像素为起点。
- 内容区使用实底，玻璃效果限于现有侧栏和快捷控制区域；不增加装饰背景、持续动画或嵌套卡片。
- 浅色、深色、长中文名称和 100%／125%／150%／200% DPI 都纳入布局设计。长组合键可省略，tooltip 和可访问名称保留完整文本。
- 新弹窗内容超出屏幕可用空间时使用统一的 `QuietScrollBar`，不靠放大窗口或缩小字号解决。
- 沿用运行时编辑锁定、弹窗屏蔽全局触发、危险操作确认和现有按键释放机制。仅第 14 项“选择当前段”属于运行控制，可在运行中操作；修改段定义仍需停止。

**用途**：已有一套能用的配置，复制后只修改少数按键或间隔，不必重新录入。按键配置与循环配置分别支持。

**界面**：配置工具栏“复制”，打开命名弹窗，预填“原名称（副本）”。创建完成后选中新副本，不自动启动。

**实现**：

- 在现有 `ProfileController`、`MacroController` 中增加复制操作，复用现有 coordinator 的保存和刷新流程。
- 复制按键／步骤、模式、间隔、暂停键、快捷键、点位和别名；按现有主键作用域分配新配置 ID、绑定 ID 和步骤 ID。
- 复制快捷键沿用当前“只有激活方案响应”的规则，切换／启用时继续执行已有冲突检查。
- 运行状态和当前切换位置不复制；新副本放在原方案之后。

- [x] 已实现：配置工具栏复制入口、命名弹窗、参数与别名复制及预览状态同步完成。

### 2. 配置备注

**用途**：把 `F1` 标成“单体宏”、`F2` 标成“群攻宏”，降低配置和多段切换的辨认成本。

**界面**：现有按键、循环步骤编辑弹窗增加可选“名称”。列表中“按键”和“名称”独立成列，未命名显示“—”，长名称省略后可悬停查看全文。悬浮窗在相关信息项中同时保留别名和实际键位。

**实现**：

- 为按键绑定和循环步骤增加可选别名，同步保存、复制、分享和导入预览。
- 别名仅用于展示，冲突判断始终使用实际按键／组合键。
- 多段宏的段名优先复用对应切换绑定的别名，不再维护另一套相同名称。

- [x] 已实现：别名覆盖按键／循环步骤编辑、列表、保存、复制、分享导入预览和悬浮窗；循环当前步骤可显示名称与实际键位。总览图待对应功能实现时直接复用别名。

### 5. 循环步骤编辑增强

**现状**：`MacroStepRow.qml` 已有拖动排序和 `Alt+↑/↓`，继续使用。新增重点是插入、复制和多选操作。

**界面**：

- 行菜单提供“在前面插入”“在后面插入”“复制此步骤”；复制后放在原步骤后方。
- 列表第一列常驻选择框，表头支持全选；勾选任意步骤后，标题区切换为“已选 N 项／复制／删除／取消选择”。多项复制保持原顺序，插在最后一个所选步骤之后。
- 插入或单步复制后只滚动定位新步骤，不改变选择状态。批量删除显示数量，并沿用删除确认。
- 正常模式继续保留双击编辑、行内编辑／删除及现有排序手柄。

**实现**：

- 为循环步骤增加稳定 ID。当前步骤按内容形成展示标识，相同内容不能唯一定位；复制、多选和重排后需要用普通主键明确指向具体步骤。
- 编辑和移动保留步骤 ID，复制和新建分配新 ID。视图选择状态按 ID 保存，切换配置或删除后清理无效选择。
- 批量操作先生成完整结果再提交，统一保存和刷新一次。

- [x] 完成标准：两个完全相同的步骤也能分别选择、移动和删除，不会误操作另一条。

### 6. 批量修改参数

**用途**：一次调整多个按键／步骤，减少重复打开弹窗。

**界面**：复用第 5 项的批量选择方式，点击“修改参数”打开弹窗。每个字段先选择“是否修改”，未选择的字段保留原值；不以空字符串或特殊数字暗示“保持不变”。

**可修改范围**：

- 按键列表：启用状态、模式、间隔、是否参与按压优先。
- 循环列表：启用状态和间隔；后续动作类型扩展时支持适用的保持时长／等待时长。
- 实际按键、别名和固定点位逐条编辑，避免一次把多行误改成同一目标。

**实现**：

- controller 在内存中生成候选配置，沿用已有按键冲突和参数合法性检查，全部通过后整体写回。
- 任一项不合法时不部分保存，明确指出出问题的行和原因。
- 长按模式不应用连发间隔；按压优先只应用于按压模式；不适用的字段在弹窗说明影响范围。
- 不改变步骤顺序，不通过“排序”改变循环的执行含义。

- [x] 完成标准：只修改勾选字段；失败时没有半套参数已被保存的情况。

### 7. 循环时长预览

**用途**：编辑时就知道一轮大约多久、执行指定轮数大约多久。

**界面**：循环列表下方显示一行“6 步 · 单轮预计 2.4 秒 · 10 轮预计 24 秒”。无限循环显示“持续循环”；按压模式显示“按住期间持续执行”，不展示有限结束时间。

**实现**：

- 时长由 core 中统一的动作时长计算提供，页面和引擎使用一致的语义，不在 QML 里另外加一遍延迟。
- 当前引擎每步是“按下 → 保持统一脉冲时长 → 松开 → 等待步骤间隔”。目前基础估算应包含每步 `kInputPulseWidthMs`（当前 5ms）及 `delayAfterMs`，末步间隔也计入本轮。
- 现有说明将步骤间隔描述成“本步按下到下一步按下”，与实际实现有出入；实施时同步修正文案，将字段明确称为“松开后间隔”，不悄悄改变已有执行节奏。
- 第 17 项落地后，分别计算点击、保持、纯等待以及显式按下／松开的耗时；不对即时动作强加额外等待。
- 用足够范围的整数累计毫秒，展示时再换算。实际调度、驱动开销和暂停会影响完成时间，界面用“预计”，不承诺精准结束时刻。

- [x] 完成标准：修改步骤、顺序、动作类型或循环次数后，摘要同步变化；按压／无限模式不显示误导性的总时长。

### 10. 一键复制诊断信息

**用途**：用户反馈“没有反应”时，可以一次提供足够的环境和错误信息。

**界面**：驱动管理页增加“诊断信息”次要操作；自检完成后也提供入口。弹窗先展示可读报告，再由用户点击“复制”，复制成功在弹窗内提示。

**报告内容**：软件版本、Windows／进程架构、当前驱动模式、运行库及设备状态、现有安全环境自检结论、最近相关错误，以及按键／循环是否启用和是否被前台限制暂停。

**实现**：

- 汇总已有 `DdRuntimeService`、`CodeIntegrityInspector`、输入驱动状态和诊断日志的相关低频错误；不逐次记录按键输入。
- 只取报告需要的字段，不直接复制整个 `config.json` 或完整日志目录；错误路径中的个人目录名应做去标识处理。
- 报告对象放在实际的诊断／core 类型目录，协调器负责组织和复制，不把数据实体直接塞进 service。
- 沿用已有自检的后台任务方式，避免读取事件日志等操作阻塞主界面。报告保留可读文本，不增加自动上传和联网诊断。

- [x] 完成标准：报告能清楚说明当前状态，复制内容与预览一致，不夹带个人路径、剪贴板内容或整套配置。

### 12. 组合键支持

**用途**：支持游戏中已经绑定为 `Ctrl+1`、`Alt+Q` 等组合的键位，也可把组合键设置为启停、暂停和切换快捷键。

**界面**：沿用现有录制按钮，提示“先按住修饰键，再按主键”；录制结果显示完整组合。首批支持 Ctrl、Shift、Alt 与一个键盘／鼠标主键；现有单独 Ctrl 等暂停键用途继续保留。

**实现**：

- 原始物理事件继续使用单键描述；配置层增加明确的组合键类型，表达修饰键集合和主键，不能用展示字符串反向判断按键。
- 录制、冲突检查、存取、分享、全局 hook、两类引擎、驱动路由和界面格式化使用同一套组合键规则。
- 同一主键按下时按具体修饰键状态匹配，组合规则命中后不同时触发该主键的单键规则。已开始的按压组合，释放主键或必需修饰键时立即结束。
- 输出组合键时按修饰键、主键顺序申请按下，按相反顺序结束；在现有路由里维护持有关系。不能直接发送一串无来源的按下／松开，影响其他规则或用户物理按住的修饰键。
- 组合键不附带通用的“触发 A、输出 B”映射功能；按压规则仍然围绕同一个配置组合键控制和输出。
- 维持现有快捷键冲突和鼠标主键限制；遇到不支持的系统保留组合直接给出说明，不降级成其中一个单键。单独 Ctrl／Shift／Alt 作为启停、切换或暂停键时，不能与使用同一修饰键的组合键同时启用，避免修饰键先行生效。

- [x] 完成标准：组合录制和显示一致，按压结束及时，Ctrl+1 不误触单独 1，多个来源共同使用修饰键时不会提前松开。

### 14. 多段宏管理

**这里的“段”是什么**：游戏内多段宏分别放在 F1、F2、F3 等快捷键上，小叽选择当前要连发的那一段。首轮以现有“切换模式”的一个绑定对应一段，不增加嵌套循环或多个互斥组。

**界面**：

- 只有配置了切换模式按键时，才在列表下方展开“当前段：[单体宏 F1 ▼] [上一段] [下一段] [回首段]”。窄窗口允许分行。
- 下拉列表按执行顺序显示所有已启用段；段名使用第 3 项别名，未填写时显示实际键位。
- 原有“切换键”继续表示下一段；旁边增加“切换设置”，集中配置上一段／下一段／回首段快捷键，避免把所有录制按钮铺在主界面。
- 当前段选择器和上一段／下一段属于运行控制，可以在运行时操作；新增、删除、改名、改快捷键及重排仍保持编辑锁定。

**实现**：

- 扩展 `RepeaterEngine` 现有当前任务 ID 和切换逻辑，增加前一段、回首段及按 ID 选择操作。
- 上一段、下一段循环切换并跳过未启用绑定；无可用段时不输出，只有一段时禁用无意义的翻段按钮。
- 切换时按现有来源释放机制结束旧段，再激活新段。停止后通过界面选段只修改待选位置，不会自动开始输出。
- 沿用现有“记住切换位置”的行为范围，不在本项顺带增加跨程序重启的运行状态保存。
- 只在这一组切换绑定内部选段，不切换整套配置，不重新启动其他独立运行的模式。

- [ ] 完成标准：按钮、快捷键、列表和悬浮窗指向同一段，禁用段不会被切到，运行中切段不遗留旧按键。

### 17. 更完整的循环动作

**用途**：能够表达“按住一个键，同时执行其他操作”和“等待一段时间”，不再每一步都只能快速点击。

**界面**：

- 循环步骤编辑弹窗增加“动作类型”，按类型显示必要字段。
- 列表将“按键”列扩展为“动作”，例如“点击 F1”“保持 Q 500ms”“按下 Ctrl”“松开 Ctrl”“等待 1秒”；末列显示适用的等待信息。
- “添加按键”在循环页改为“添加步骤”，按键连发页继续沿用原名称。
- 不适用的按键或点位字段直接隐藏；纯等待不要求用户录制一个虚假的按键。

| 动作类型 | 含义 | 主要字段 |
| --- | --- | --- |
| 点击 | 按下后按脉冲时长松开，再等待 | 按键／组合键、松开后间隔、可选鼠标点位 |
| 保持 | 按住指定时长后松开，再等待 | 按键／组合键、保持时长、松开后间隔 |
| 按下 | 维持按下状态，交给后续步骤松开 | 按键／组合键、动作后等待 |
| 松开 | 释放本循环此前持有的按键 | 按键／组合键、动作后等待 |
| 等待 | 仅等待，不发送输入 | 等待时长 |

**实现**：

- 把 `MacroStep` 从“单键＋间隔”扩展为明确的动作类型及对应参数；数据类型位于 core／实际结构目录。
- 引擎由当前单个 `keyDown` 状态扩展为当前动作阶段、剩余时长和本循环持有的按键集合；继续使用现有高精度等待与输入路由。
- 使用普通的动作合法性检查发现“未按下就松开”“一轮结束仍有未配对按下”等情况，并指出具体步骤；不另建哈希、基线或门禁体系。
- 暂停时释放本循环输出的全部持有键并冻结剩余时长；恢复时按逻辑状态重建仍需保持的键、继续剩余时间，已经完成的点击不重复执行。
- 停止、配置切换、程序退出时释放本循环全部持有键并清理进度。暂停、停止时都不得释放其他来源仍在使用的键。
- 对显式按下／松开和组合点击间的重叠持有进行统一计算，不能让一次点击提前松开此前明确保持的 Ctrl。
- 同步更新配置读写、分享预览、步骤编辑、批量修改、时长估算、模板和使用说明。录制一整串真实操作属于未选中的第 16 项，不附带实施。

- [ ] 完成标准：“按下 Ctrl → 点击 1 → 等待 → 点击 2 → 松开 Ctrl”能清晰编辑，暂停及停止后没有残留按键，时长和进度按动作语义计算。

### 22. 键盘与鼠标总览图

**用途**：查看当前配置占用了哪些键，各自承担什么角色，并快速进入相应编辑。

**界面**：

- 列表标题旁提供“按键总览”，打开可调整尺寸的辅助弹窗，不替换主列表。
- 上部显示键盘示意，下部显示鼠标按键，旁边显示当前选中键的角色、别名、模式和间隔。
- 标识启停、暂停、切换、输出等用途。同一物理键可能参与多个组合，显示多个标记并在详情列出，不能简化成只有一种状态。
- 点击某键后先选中并展示详情；有多个相关规则时先选择目标，再调用现有编辑弹窗。未配置的键提供“添加”入口。
- 循环模式下同一键可能出现多次，详情列出对应步骤并跳转；纯等待仍从步骤列表编辑。
- 运行时允许查看，编辑入口保持锁定；只展示小叽当前方案的配置和运行状态，不持续记录用户在其他程序输入的内容。

**实现**：

- 从现有页面模型生成按键用途投影，不维护另一份可独立修改的配置副本。
- 使用 QML 控件／矢量布局绘制，按可用宽度缩放并设置最小可点击尺寸；窄窗口可滚动，支持 Tab 导航和完整可访问名称。
- 区分已配置、当前运行和暂停状态，同时使用标记／文字表达，不能只靠颜色或发光动画。
- 明确总览是标准键位示意，不宣称自动识别用户物理键盘型号。非常见键通过补充列表仍可查看和编辑。

- [ ] 完成标准：总览与列表始终一致，组合键和重复步骤不会丢失关联，图中修改仍走同一套保存与冲突检查。

## 四、第 23 项到底是什么

**它管理的是游戏自己的角色设置文件，与小叽配置方案不同。**

例如，你把角色 A 的技能快捷键、界面位置和插件设置调好了，想让同一台电脑上的角色 B 也使用相同设置。这个功能会定位 A、B 的角色数据，选择要复制的部分，先备份 B 的相关内容，再把 A 的设置复制过去。也可以把 A 的设置导出为备份，以后恢复或带到另一台电脑。

| 操作 | 涉及什么 | 与第 1 项的区别 |
| --- | --- | --- |
| 复制小叽配置 | 小叽内部的连发规则、循环步骤、快捷键等 | 只管理我们自己的配置数据 |
| 角色键位／插件备份同步 | 游戏客户端保存的键位、界面或指定插件配置 | 会读写游戏目录中的角色文件 |

若以后决定做，建议先做本地功能：

- 由用户选择游戏目录、源角色和目标角色，明确展示可处理的文件分类，不猜测角色映射。
- 首轮只支持实际核实过的客户端和文件分类，不整目录覆盖。
- 独立弹窗展示要备份／覆盖的内容、目标角色和备份位置；沿用不可逆操作的确认要求。
- 写入前确认游戏不在占用这些设置，保存目标原文件；出现失败时恢复本次已修改文件，提供明确的恢复入口。
- 不处理账号密码、登录凭据，不在这一项顺带加入账号管理或云服务。

**当前状态：只保留说明，不纳入本轮实施。** 如果实际需求只是“给另一个角色准备一套小叽按键”，第 1 项复制配置已经可以解决。
