# 按键模式与冲突

## 各模式的作用

下表中的“启动”指右侧启动按钮或方案的启停快捷键。停用的按键不参与运行。

| 模式 | 开始条件 | 输出 | 结束或切换条件 |
| --- | --- | --- | --- |
| 开关 Toggle | 启动工具 | 按间隔连发 | 停止工具 |
| 按压 Hold | 工具运行时物理按住配置键，组合键需按住所需修饰键和主键 | 按间隔连发 | 松开主键或所需修饰键 |
| 独立 Independent | 工具运行时按一次该配置键 | 当前选中项按间隔连发 | 再按一次关闭；按另一个独立键切换。松开键或修饰键不清除选择 |
| 切换 Sequence | 启动时选中第一段或记忆段 | 当前段按间隔连发 | 按切换键进入下一段；停用段跳过 |
| 长按 LongPress | 启动工具 | 持续按住配置键；组合键的修饰键和主键都按住 | 停止工具时释放 |

按压是“物理按住时连发”，长按是“由程序持续保持按下”。组合键连发只让修饰键保持，主键仍按下约 5ms 后松开，再等待该项间隔。

## 哪些模式会同时输出

每个方案只有一个独立选择和一个切换段选择，但两者彼此独立，可以和开关、长按一起运行。

| 两项的模式 | 能否同时输出 |
| --- | --- |
| 独立 + 独立 | 否，选择互斥 |
| 切换 + 切换 | 否，当前段互斥 |
| 按压 + 其他模式 | 开启按压优先且该按压项参与优先时互斥；否则可以并发 |
| 按压 + 按压 | 可以并发；参与优先不会暂停其他按压项 |
| 其余组合，包括独立 + 切换 | 可以并发 |

暂停键暂停开关、独立、切换并释放长按，按压仍可运行。按压优先释放其他模式的输出，但保留独立选择和切换位置，接管结束后恢复。

游戏前台限制挂起时所有输出释放，运行选择保留。前台窗口切换时，长按及组合键先释放，等待 50ms 焦点稳定后按当前状态恢复；纯单键连发沿用原有规则。

## 冲突判断

先区分输入触发歧义和输出冲突，再应用上面的并发关系。仅有相同修饰键不构成冲突。

- 同一按键和同一模式不重复配置。不同模式的停用备选可以保留，启用时再按实际模式关系校验。
- 同一完整按键不能同时承担按压触发和独立启停触发；单独修饰键的独立启停也不能与使用它的按压或独立组合键混用，因为修饰键按下时会先触发一次独立启停。长按已经覆盖按压或独立触发所需的主键及修饰键时，也不能依赖同一次物理按键触发，因为现有长按防干扰过滤会拦住该主键。
- 启停、暂停、切换等立即生效的控制键沿用原有占用检查。单独修饰键作为这些控制键时，不能再用作连发组合键前缀。
- 可以同时输出的两项不能争用同一主键，也不能要求不同的显式修饰键状态。例如持续按住 Ctrl+Alt 会把另一项的 Ctrl+1 改成 Ctrl+Alt+1。
- 同样的修饰键、不同主键允许并发，例如 Ctrl+1 和 Ctrl+2。共享 Ctrl 的一项结束时，另一项仍可继续使用 Ctrl。
- 单独修饰键的长按是明确的持续保持功能，可供普通键连发组成组合，也可与需要该修饰键的组合键共享。例如“Ctrl 长按 + 1 开关”会输出 Ctrl+1，“Ctrl 长按 + Ctrl+1 开关”也允许；“Alt 长按 + Ctrl+1 开关”会改变显式组合键的含义，不能同时启用。
- 单独修饰键的连发不能替代长按保持；与需要修饰键稳定按住的组合项并发时会被拒绝。

| 配置示例 | 结果与原因 |
| --- | --- |
| Ctrl+1 开关 + Ctrl+Alt+1 开关 | 拒绝同时启用：主键和修饰键状态互相干扰 |
| Ctrl+1 独立 + Ctrl+Alt+1 独立 | 允许：同一时间只选中一个 |
| Ctrl+1 切换 + Ctrl+Alt+1 切换 | 允许：同一时间只运行当前段 |
| Ctrl+1 开关 + Ctrl+Alt+1 按压，开启按压优先且该项参与 | 允许：按压期间释放开关项，结束后恢复 |
| 上一项取消按压优先或取消参与优先 | 拒绝修改：修改后两项可能同时输出 |
| Ctrl+1 开关 + Ctrl+2 开关 | 允许：主键分别脉冲，Ctrl 共同保持 |
| Ctrl 长按 + Ctrl+1 开关 | 允许：复用同一个 Ctrl 持有请求 |
| Ctrl 开关 + Ctrl+1 开关 | 拒绝：Ctrl 连发的松开会破坏组合键保持 |

新增、启用、模式修改、批量编辑、方案启用、按压优先修改和启动均覆盖上述规则。Mac/Windows 预览与正式程序共用 `RepeatModeRules`，预览只处理内存示例。

## 输出实现

`RepeaterEngine::SyncOutputsLocked()` 汇总当前生效项需要的实际按键，按物理组件去重。长按键和组合键修饰键都调用原有 `InputDriver::SendHeldDown()`；瞬时主键调用 `SendDown()`，结束调用 `SendUp()`。没有额外的组合键模式或路由器专用修饰键状态机。

每次状态变化先释放不再需要的主键和修饰键，再申请当前输出；修饰键先按下，主键先释放。被多个生效项使用的组件持续保留，避免其中一项的松开影响另一项。

真实修饰键事件保持通行，物理状态只由已有物理输入通道更新。运行时“是否已长按”的查询不写入物理按下状态，避免将程序注入的修饰键误判为物理按住，导致下一次启动跳过修饰键。录制及 Raw Input 解析保持原有实现。

循环连发沿用现有点击、保持、按下/松开和逐键来源仲裁，不套用本页的方案内模式互斥规则。循环中的“按下 Ctrl → 点击 1 → 松开 Ctrl”等跨步骤保持继续由现有宏输出管理；这里复用的是两者共同的驱动持有入口。
