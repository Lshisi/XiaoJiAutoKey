使用方法与判断依据
  1. 测试小叽输出前，在“全局设置 → 生效范围”临时关闭“仅游戏客户端前台时生效”。先只启用要观察的项，连发间隔可先用 100–200ms。
  2. 启动小叽，回到本页点击“开始接收”，把鼠标放在接收区内。操作页面按钮产生的点击不计入鼠标测试。
  3. 普通连发应不断出现主键的 down / up；组合连发还应在每个主键事件中携带对应的 Ctrl / Alt / Shift 标志；长按可能出现 repeat，松开前不应出现该键的 up。
  4. 切换窗口、编辑筛选或暂停接收会中断观察，将按住状态标为未知，不会补造松键事件，也不会把中断期间算入下一次连发间隔。
  5. 停止小叽后，重新聚焦接收区，手动按一次 A 或移动鼠标；用新事件的修饰键标志、鼠标 buttons 判断是否松开。测完恢复游戏前台限制。
  • 本页观察浏览器实际收到的事件，无法区分物理输入和小叽/DD 驱动输出。系统快捷键、浏览器保留快捷键和部分媒体键可能无法送到网页。
  • 鼠标左键 / 中键 / 右键 / 侧键4 / 侧键5 的 button 分别为 0 / 1 / 2 / 3 / 4；buttons 是按住集合的位掩码，依次对应 1 / 4 / 2 / 8 / 16。
  • 滚轮原始 deltaX / deltaY / deltaZ 及 deltaMode 会保留，正负值表示方向；不同设备可能合并滚轮事件，事件次数不能直接当作滚动格数。
  • 按下次数包含 repeat=true 的键盘重复事件；鼠标 click / auxclick / dblclick 单独记录，不会额外增加 down / up 次数。
  • 实时状态跟随浏览器画面刷新，触发余光保留 120ms，统计和日志最多每 125ms 批量更新。多个短按可能落在同一画面内，使用次数和日志核对；余光不会延长真实按住时长，也不会延迟或回放输入事件。
  • 数据保存在页面内存，刷新或关闭即清除。仅在点击“导出 JSON”时下载本地文件；导出包含累计统计及最近 2,000 条事件，不受筛选和冻结影响。页面无需网络和安装。
